DevPulse — Issue & Feature Tracker

A role-gated internal tracker where contributors and maintainers file bugs and feature requests over an explicit, audit-friendly REST API built on raw SQL.

Overview

DevPulse is a role-gated internal tracker where software teams report bugs and feature requests and coordinate their resolution. Two roles — Contributor and Maintainer — define who can create, update, and delete issues.

The API is deliberately built on raw SQL through the pg pool rather than an ORM, so every query is explicit and easy to audit. Auth is a stateless JWT layer, and access is enforced per-role and per-owner on the server.

Key features

  • Signup and login returning a JWT.
  • Role-based access control: contributors manage their own issues; maintainers can update any issue, change statuses independently, and delete issues.
  • Issue types (bug / feature_request) and a workflow status (open / in_progress / resolved).
  • A full REST surface — list, create, read, update, and delete issues — all JWT-protected.
  • Consistent JSON requests and responses with a standard error shape.
  • Database constraints: unique email, required fields, and a minimum description length.

Challenges faced

  • RBAC without an ORM's help

    With no ORM to lean on, every ownership and role check is explicit, parameterised SQL. It was more code, but each rule is visible and testable.

  • Owner-only edits vs. maintainer overrides

    A contributor can only edit issues they own, while a maintainer can edit anything. Encoding that asymmetry cleanly in the handlers — not scattered through the UI — was the crux of the project.

  • Enumerated values and clear errors

    Issue type and status are fixed sets. Validating them and returning a clear, consistent error instead of a raw database failure took care.

  • Staying injection-safe

    Writing raw SQL means every query must be parameterised. Keeping that discipline across the whole codebase was non-negotiable.

Potential improvements & future plans

  • Comments and an activity timeline per issue.
  • Labels, assignees, and due dates.
  • Pagination, sorting, and richer filtering.
  • Email notifications on assignment and status change.
  • Automated tests (integration against a test database) and CI.
  • Migrate to Prisma for type safety while keeping the same API contract.
