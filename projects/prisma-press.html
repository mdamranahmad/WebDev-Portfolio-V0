Prisma Press

A publishing platform planned like a product — requirements first, then a type-safe schema and a testable API contract, with a Next.js frontend on top.

Overview

Prisma Press is a publishing platform built backend-first. Before any code, I wrote a backend requirement analysis that pinned down the models, roles, and endpoints.

The schema then lived in Prisma for end-to-end type safety, and every endpoint was documented as a Postman collection so the API was a contract rather than a guess. A Next.js App Router frontend provides the authentication and blog pages that consume the API.

The point of the project wasn't the feature list — it was the discipline: keeping the requirements doc, the Prisma schema, and the API tests traceable to the same source of truth, the way maintainable products are built.

Key features

  • A written requirement analysis committed alongside the code — the source of truth for models and endpoints.
  • A Prisma schema providing type-safe queries across the backend.
  • Authentication and content endpoints documented in a Postman collection.
  • A Next.js App Router frontend with authentication and blog pages.
  • A consistent response envelope across the API so the frontend never has to defensively parse.

Challenges faced

  • Agreeing on the model before writing code

    It's tempting to start with a screen and let the data model emerge. Writing the requirement analysis first meant the frontend was never guessing what the API returned.

  • Keeping three sources of truth aligned

    The requirement doc, the Prisma schema, and the Postman tests all describe the same API. Treating the schema as the anchor kept them from drifting apart.

  • Predictable responses

    Every endpoint returns the same envelope shape, so the frontend consumes responses uniformly instead of branching per endpoint.

Potential improvements & future plans

  • A fuller editorial workflow: drafts, review, and scheduled publishing.
  • Media uploads (for example Cloudinary) for cover images and inline images.
  • Search, tagging, and pagination for posts.
  • Role-based authoring (admin / author / reader) with permissions enforced on the API.
  • Automated tests and CI, plus a one-command local setup.
  • Deploy the frontend and API and link a public demo.
