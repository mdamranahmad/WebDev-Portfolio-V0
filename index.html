01 — About

Backend-first, all the way to the screen.

I like the parts of a system users never see but always feel — the data model, the API contract, and the error handling that keeps everything steady.

I'm a software engineer with a backend-first mindset. I care about the parts of a system that users never see but always feel — the data model, the API contract, and the error handling that keeps everything steady when things go wrong.

In practice that means I model the entities and relationships, decide what the API contract looks like, and only then start shaping what the user actually sees and clicks. I build the backend and the Next.js frontend that consumes it, so I can take a feature from schema to screen.

I'm comfortable designing REST endpoints validated with Zod, enforcing role-based access control on the server, wiring real payment and notification flows, and wrapping multi-step operations in transactions so nothing is left half-finished.

  • 01

    Model the data

    Entities, relationships, and constraints get sketched — usually as a real ERD — before a single component exists.

  • 02

    Build the contract

    A typed, authenticated API layer the frontend can rely on without second-guessing what comes back.

  • 03

    Craft the interface

    A Next.js / React frontend that consumes that contract directly — responsive and honest about loading and error states.
